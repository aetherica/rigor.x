# Security Policy

## Supported versions

Security fixes are currently evaluated against the latest development version on the canonical `main` branch. No stable release has been published yet.

## Reporting a vulnerability

**Do not open a public issue for a suspected vulnerability.**

Use GitHub's private vulnerability reporting / Security Advisories feature for this repository, if enabled. If private reporting is unavailable, contact the repository owner through a verified private channel before sharing technical details publicly.

Include:
- affected commit, file, component, and version (if known);
- impact and realistic attack scenario;
- reproducible steps or a minimal proof of concept;
- suggested mitigation, if any.

Please allow time for triage and coordinated disclosure. Do not publish exploit details before a fix or disclosure agreement.

## Response expectations

This is an owner-maintained development project; no guaranteed response or remediation SLA is currently offered. Reports will be triaged in good faith, and severity, affected scope, and remediation status will be documented where safe to do so.

## Scope

Do not test against systems, endpoints, accounts, or data that you do not own or have explicit permission to test. Avoid destructive testing, denial of service, privacy violations, and data exfiltration.
